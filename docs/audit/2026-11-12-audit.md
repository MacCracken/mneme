# mneme — Security and correctness audit (2026-11-12, 1.2.3)

**Scope:** the whole Cyrius port (`src/*.cyr`, 12,248 lines at 1.2.2), at toolchain 6.7.18. This is the re-audit
the [2026-07-10 audit](2026-07-10-audit.md) asked for "when a listening socket is added": `mneme serve` (1.1.0)
added one.

**Method:**
- **Three read-only review lanes:** network/untrusted input (`mcp_*`, `net_http`, `api_server`, `main`), storage
  and import/export (`store_*`, `io_*`, `core_config`, `core_frontmatter`), and search/ai/ui/core. Each was
  cross-checked against `rust-old/`.
- **Manual verification** of every finding before repair.
- **Regression tests:** each repair has one, and the important ones were mutation-proven (reapplying the old
  behaviour turns the suite red).
- **Live tests** of `mneme serve` (with curl) and the TUI.

**Result:**
- 39 defects repaired in 1.2.3: 4 critical, 15 high, 13 medium and 7 low.
- 11 further items are deferred to named releases with a reason. None of them is reachable remotely in a way that
  loses data, but #5's memory growth is a resource-exhaustion item.
- The suite went from 62 files / 1,170 assertions to 63 / 1,328, all green.

## Threat model (updated)

mneme is a local, single-user knowledge base: a TUI, an in-process HTTP router (`api_server`, used only by tests
today), and since 1.1.0 **`mneme serve`**. That is a single-threaded, **unauthenticated** HTTP endpoint for MCP
`tools/call`, which daimon hosts.
- **Untrusted input:** MCP request bodies, note titles, content and tags, imported files, clipped HTML, and daimon
  and embedding responses.
- **New since 2026-07-10:**
  - the socket (remote crash, denial of service, data access);
  - the user's own web browser (a page posting to `127.0.0.1`);
  - every `tools/call` field as a path into the store.

## Repaired in 1.2.3

### Critical — silent loss of notes or index state

| # | Finding | Where | Repair |
|---|---|---|---|
| 1 | A title- or tag-only update of a note whose file could not be read rewrote the note with **no body** and returned success | `store_vault.cyr` update_note | Fails before any write (Rust: `read_note(..)?`); get_note likewise |
| 2 | Every note read went through a fixed 256 KB buffer: a larger note came back cut short, and saving it after an edit destroyed the rest | `store_files.cyr:44` | `file_read_whole` |
| 3 | The training log's append re-read the log through a 1 MB buffer and **rewrote** it, so past 1 MB every append destroyed everything after the first megabyte (measured: 20,000 lines → 15,651); it returned 1 even when the write failed | `ai_training_export.cyr` | `file_append_locked` (O_APPEND under a lock), result checked |
| 4 | The full-text index keyed documents by the uuid handle's **address**: an update through the API/MCP added a duplicate (stale title in results), a delete left the note searchable | `search_engine.cyr` | Keyed by the uuid's value |

## Deferred, with where they land

| Finding | Why not now | Release |
|---|---|---|
| `mneme serve` memory grows with every request (bump allocator, nothing freed; the JSON tree is the largest share) | Needs a per-request arena plus deep copies of every stored string — a design change, not a repair. Loopback-only by default limits who can drive it | 1.4.x |
| No authentication once `MNEME_BIND` widens the bind | A shared-secret header needs daimon to send one | 1.4.x |
| Titles over 255 bytes cannot be stored (patra STR columns) | Now fails loudly instead of silently; TEXT columns are not comparable in WHERE/ORDER BY, so it needs query rework | 1.4.x |
| Non-ASCII text: slugs map every byte ≥ 0x80 to `-` (an all-CJK title becomes `.md`), the tokenizer splits on them, tag trimming drops them | Needs Unicode classification (`lib/unicode` is now vendored via bayan) across four modules | 1.4.x |
| `core_config` round-trip drops `[context_retrieval]` and other embedding keys; `_cfg_f64_str` mishandles negatives and huge values | No caller in `src/` yet | 1.4.x |
| TUI: no raw mode, and a multi-byte read decodes only its first key | Terminal (termios) work | 1.4.x |
| Version store and context buffer compare uuids by pointer | Neither is wired; the context-buffer test uses integer ids | 1.4.x |
| Frontmatter renders titles/tags raw (a title with `\n---` injects keys) | rust-old behaves the same | 1.4.x |
| Temporal API returns only `total_notes` where Rust returns the whole report | Serialization of the full report | 1.4.x |
| Consolidation is O(n²·U²); concept dedup and other sorts are quadratic | Performance | 1.5.x |
| Semantic engine hard-codes dimension 384 | Lands with live embeddings | 2.0.0 |

## Checked and sound

- **SQL:** `_db_sql_str` escaping matches patra's tokenizer; every value goes through it.
- **sandhi's server:** it refuses oversized and duplicate Content-Length, CL with TE, duplicate Host, and requests
  over 64 KiB.
- **bayan JSON:** values are type-checked (`is_str`), and nesting is capped at 128.
- **Secrets:** headers reject CR/LF/NUL, so `api_key` cannot inject a header, and it is never logged.
- **Self-registration:** it sends only tool metadata and a callback URL.
- **Parity:** SM-2, Thompson sampling, RRF (k = 60), rag_eval, the tagger and the summarizer match rust-old.
- **Arithmetic:** cosine, clustering and consolidation never divide by zero, and the f64 sorts tolerate NaN.
- **PDF export:** its write results have been checked since 1.1.2, and it passes `pdfcheck.sh --strict` 7/7.
